    Class 6.1 - SQL 中的滑动窗口函数¶

    1. 窗口函数的概念¶

    窗口函数是 SQL 中一个很重要的功能：

    • 窗口函数指的是在每一行数据上，都用窗口框出一个数据集，然后在这个数据集上进行计算
    • 这个窗口框出的数据集，运算结果，作为这一行应用了窗口函数的结果
    • 那么这个窗口框出的数据集，可以求和、平均值、最大值、最小值等，这些函数和我们在聚合函数中使用的函数是一样的

    窗口函数分为以下几种：

    • 滑动窗口函数：窗口框出的数据集是以当前行为中心，向前或向后延伸的一个固定长度的数据集
    • 扩展窗口函数：窗口框出的数据集是以当前行为中心，向前或向后无限延伸的数据集
    • 分组窗口函数：窗口框出的数据集是以当前行所在的分组为基础的数据集
    • 分组滑动窗口或分组扩展窗口函数：窗口框出的数据集是以当前行所在的分组为基础，并且向前或向后延伸的数据集

    2. 滑动窗口的概念¶

    滑动窗口指的是，窗口以当前行为准，向前或向后延伸的一个固定长度的数据集（包括当前行），这个窗口可以是：

    • 向前延伸的窗口
    • 向后延伸的窗口
    • 居中延伸的窗口，也就是向前和向后都延伸的窗口

    3. 向前延伸的滑动窗口¶

    (1) 向前滑动窗口的概念¶

    向前延伸的滑动窗口计算并不复杂，我们来看一个简单的例子：

    • 比方说我们有以下销量表，在销量表中，我们想求以下近三月的销量总和：

    • 表中有6个月份，因此，每一行都能算出来一个近三月的销量总和的数值

    • 我们在计算 2024-06 的近三月的销量总和时，窗口框出的数据集是 2024-04、2024-05、2024-06 这三行数据，接着，这三行数据求个和，得到的就是 2024-06 的近三月的销量总和的数值：

    • 接着，我们在计算 2024-05 的近三月的销量总和时，窗口框出的数据集是 2024-03、2024-04、2024-05 这三行数据，接着，这三行数据求个和，得到的就是 2024-05 的近三月的销量总和的数值：
    • 接着，我们在计算 2024-04 的近三月的销量总和时，窗口框出的数据集是 2024-02、2024-03、2024-04 这三行数据，接着，这三行数据求个和，得到的就是 2024-04 的近三月的销量总和的数值：
    • 接着，我们在计算 2024-03 的近三月的销量总和时，窗口框出的数据集是 2024-01、2024-02、2024-03 这三行数据，接着，这三行数据求个和，得到的就是 2024-03 的近三月的销量总和的数值：
    • 接着，当我们在计算 2024-02 的近三月的销量总和时，窗口框出的数据集是 2024-01、2024-02 这两行数据，虽然不满足三行的条件，但我们就按这两行数据求个和，得到的就是 2024-02 的近三月的销量总和的数值：
    • 接着，当我们在计算 2024-01 的近三月的销量总和时，窗口框出的数据集是 2024-01 这一行数据，虽然不满足三行的条件，但我们就按这一行数据求个和，得到的就是 2024-01 的近三月的销量总和的数值：

    大家注意一个情况：

    • 在 Azure SQL Database 中，如果窗口框出的数据集不满足三行的条件，那么会自动按照满足条件的行数来求和
    • 因此，2024-02 的近三月的销量总和就是 2024-01 和 2024-02 这两行数据的销量总和，2024-01 的近三月的销量总和就是 2024-01 这一行数据的销量总和
    • 然而，在有些数据库中，如果窗口框出的数据集不满足三行的条件，那么就会直接返回 NULL 作为结果，因此，2024-02 的近三月的销量总和就是 NULL，2024-01 的近三月的销量总和也是 NULL
    • 这个也是有道理的，因为我们要求的是近三月的销量总和，如果不满足三行的条件，那么就无法求出近三月的销量总和，用一个月或两个月的数据来求近三月的销量总和，结果也是不准确的，因此，返回 NULL 也是合理的
    • 在这种情况下，如果我们想求 2024-02 的近三月的销量总和，SQL 就会发现 2024-01 和 2024-02 这两行数据不满足三行的条件，因此，SQL 就会返回 NULL 作为结果：
    • 同样的道理，SQL 在求 2024-01 的近三月的销量总和时，也会发现 2024-01 这一行数据不满足三行的条件，因此，SQL 就会返回 NULL 作为结果：
    • 因此，在使用窗口函数时，我们需要注意一下数据库的这一点差异，来正确地理解窗口函数的结果

    (2) SQL 中向前滑动窗口的语法¶

    在 SQL 中，滑动窗口函数的语法如下：

    SELECT
    column1,
    column2,
    ...,
    AGGREGATE_FUNCTION(计算数值列) OVER (
        ORDER BY 排序依据列
        ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW
    ) AS 窗口函数结果列
FROM table
...
    • 其中 AGGREGATE_FUNCTION 是我们在聚合函数中使用的函数，例如 SUM、AVG、MAX、MIN 等

    • OVER 关键字表示这是一个窗口函数，接着，括号中的内容是窗口函数的设置，告诉 SQL 如何框出窗口的数据集：

      • ORDER BY 关键字表示按照哪个列来排序，这个十分重要，因为数据不排好序的话，窗口函数就无法正确地框出数据集来进行计算
      • ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW 表示窗口框出的数据集是当前行以及前面 N-1 行的数据

    • 注意我们这里为什么要强调 N-1 呢：

      • 因为当前行和 N-1 行中间正好框出了 N 行数据
      • 比方说，我们想求近三个月的总和，那么我们就需要框出当前行以及前面两行的数据，这样就框出了三行数据
      • 因此，我们需要使用 ROWS BETWEEN 2 PRECEDING AND CURRENT ROW 来框出近三个月的数据集

    比方说，在上面的月份销量例子中，求近三月的销量总和的 SQL 语句如下：

    SELECT
    月份,
    销量,
    SUM(销量) OVER (
        ORDER BY 月份
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS 近三月销量总和
FROM 销量表

    4. 向后延伸的滑动窗口¶

    (1) 向后滑动窗口的概念¶

    当然，滑动窗口函数也可以向后取数据：

    • 例如，我们想求未来三月的销量总和，那么我们就需要框出当前行以及后面两行的数据，这样就框出了三行数据：
    • 注意，不论窗口向前还是向后延伸，我们都要确定，当前窗口是给哪一行计算的，并不是说滑动窗口永远都是给窗口框出的最后一行计算的，因此，在上面的例子中，窗口函数是给 2024-03 这一行计算的，而不是给 2024-05 这一行计算的

    (2) SQL 中向后滑动窗口的语法¶

    SQL 中向后取数据的语法结构为：

    SELECT
    column1,
    column2,
    ...,
    AGGREGATE_FUNCTION(计算数值列) OVER (
        ORDER BY 排序依据列
        ROWS BETWEEN CURRENT ROW AND N-1 FOLLOWING
    ) AS 窗口函数结果列
FROM table
...

    • 这个语句和上面的语句的区别在于：

      • 向前取数据的滑动窗口函数使用的是 ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW 来框出数据集
      • 向后取数据的滑动窗口函数使用的是 ROWS BETWEEN CURRENT ROW AND N-1 FOLLOWING 来框出数据集
      • 在这两种情况中，在 BETWEEN 和 AND 之间的部分逻辑是一样的，前面的行要写在前面，后面的行要写在后面

    • 然后，向后取数据的滑动窗口使用的场景是比较少的：

      • 因为在数据分析中，我们通常是按照时间来分析数据的，向后取数据就是按照未来的时间来分析数据的
      • 这个会涉及到一个严重的问题就是未来数据泄露
      • 比方说我们分析 2024-06 的销量总和时，我们把 2024-06、2024-07、2024-08 这三个月的数据
      • 这个情境下，我们仿佛在 2024-06 的时候就知道了 2024-07 和 2024-08 的数据了
      • 然而当我们立足当下，我们在本月是无法知道未来几个月的数据的
      • 因此，我们通常不向未来取数据，这会造成我们的分析结果过于乐观，无法反映现实的情况

    例如我们想求未来三月的销量总和，那么 SQL 语句如下：

    SELECT
    月份,
    销量,
    SUM(销量) OVER (
        ORDER BY 月份
        ROWS BETWEEN CURRENT ROW AND 2 FOLLOWING
    ) AS 未来三月销量总和
FROM 销量表

    向后的滑动窗口使用情境比较有限，我们就不在数据库中来演示了，大家可以自己在数据库中尝试一下。

    5. 居中取数据的滑动窗口函数¶

    (1) 居中滑动窗口的概念¶

    通过上面两种情况，我们发现窗口函数的定义语法中，ROWS BETWEEN ... AND ... 其实就是在定义窗口框出的数据集的范围

    • 这个范围其实是可以随便定义的，只需满足前面的行要写在前面，后面的行要写在后面就可以了，如果按时间排序的话就是历史在前，未来在后
    • 因此，我们也可以定义一个居中取数据的滑动窗口函数，也就是当前行为中心，前面 N-1 行和后面 M-1 行的数据都框出来来进行计算：
    • 例如，我们以当前月为中心，向前取一行数据，向后取两行数据，那么我们就框出了四行数据：
    • 同样要注意，并不是说窗口函数永远都是给窗口框出的最后一行计算的，窗口函数是给当前行计算的，因此，在上面的例子中，窗口函数是给 2024-03 这一行计算的，而不是给 2024-05 这一行计算的

    (2) SQL 中居中滑动窗口的语法¶

    在 SQL 中，居中取数据的滑动窗口函数的语法结构如下：

    SELECT
    column1,
    column2,
    ...,
    AGGREGATE_FUNCTION(计算数值列) OVER (
        ORDER BY 排序依据列
        ROWS BETWEEN N-1 PRECEDING AND M-1 FOLLOWING
    ) AS 窗口函数结果列
FROM table
...

    例如，我们想求以当前月为中心，向前取一行数据，向后取两行数据的销量总和，那么 SQL 语句如下：

    SELECT
    月份,
    销量,
    SUM(销量) OVER (
        ORDER BY 月份
        ROWS BETWEEN 1 PRECEDING AND 2 FOLLOWING
    ) AS 居中取数据的销量总和
FROM 销量表

    当然，居中的滑动窗口使用情境也比较有限，我们就不在数据库中来演示了，大家可以自己在数据库中尝试一下。

    6. 滑动窗口函数小结¶

    我们简单总结一下滑动窗口函数：

    • 滑动窗口的关键语法：

      • 向前取数据：ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW
      • 向后取数据：ROWS BETWEEN CURRENT ROW AND N-1 FOLLOWING
      • 居中取数据：ROWS BETWEEN N-1 PRECEDING AND M-1 FOLLOWING

    • Azure SQL Database 中，如果窗口框出的数据集不满足 N 行的条件，那么会自动按照满足条件的行数来进行计算，而不是直接返回 NULL 作为结果

    • 如果我们想要实现不满足 N 行的条件时返回 NULL 作为结果，那么我们可以在主查询中添加一个新的列来计算窗口框出的数据集的行数，然后在外层查询中使用 CASE WHEN 来实现这个功能
