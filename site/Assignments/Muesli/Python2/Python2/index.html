    Muesli - Python Project 2 - Estimating Sales Demand¶

    Project Requirements¶

    Project Objective¶

    This assignment develops the ability to analyse data and prepare information to support operational and strategic decision-making using databases and programming languages. Specifically:

    • Assess how data quality issues affect business decision-making, and implement strategies to identify and mitigate bias in operational datasets.
    • Interpret a specified algorithm and plan its implementation for processing operational data.
    • Implement the algorithm in a Jupyter Notebook using Python, managing associated files.
    • Test the implemented Python code to ensure it produces reliable outputs, including appropriate handling of data anomalies.

    Project Contents¶

    Previously, a dashboard was developed to support production planning for Muesli Pty Ltd. As part of that solution, the sales and marketing team provided the average units sold per day for each product at each warehouse, which the company uses to predict how long current inventories will take to sell out.

    • Those predictions are highly dependent on the accuracy and recency of the average daily sales figures. The company now wants to formalise and automate the process of updating the CSV file that sales and marketing originally provided.

    • The problem: internal sales data is biased — products with low or zero inventory cannot be sold, even if customer demand exists. Industry sales data is more complete but only updated monthly, so it's not timely enough for operational use.

    • The compromise: use internal sales data, but adjust for periods of low inventory availability.

    • Your task: write a Python program that estimates product demand by accounting for bias in the sales data using inventory availability. The program will run once a week to output an updated CSV file used within the dashboard.

    Estimating Potential Sales Demand¶

    Calculate an estimated average daily quantity demanded for each product at each location, using Python and SQL, based on recent sales history in the company database. The calculation must be based on a configurable time window defined as the most recent N complete Monday–Friday weeks (current default: 4 weeks), where N can be easily modified in the program.

    Step 1 - Source data from the analysis period

    • Retrieve opening inventory balances for each product and location, for the most recent N complete Monday–Friday weeks.
    • Retrieve sales transactions for the same period.
    • Determine which of the three distribution centres fulfilled each sale — a straightforward mapping based on the customer's region (see background document).
    • Important: directly joining sales transactions to inventory counts as the means of determining the location of each sale is not correct and will produce invalid results.

    Step 2 - Minimum stock level required to enable at least one sale

    • The minimum inventory threshold is defined as the quantity required to satisfy one typical customer transaction.
    • For each product, compute this as the median quantity per transaction, calculated across all sales transactions for that product (across all locations).

    Step 3 - Complete daily sales series

    • Aggregate sales data to daily level.

    • For each product and location:

      • Sum all individual sales transactions to obtain total daily sales.
      • Ensure the dataset includes all Monday–Friday days in the analysis period.
      • For days with no recorded sales transactions, explicitly record total daily sales as 0.

    • This ensures both sales-activity and non-activity days are fully represented in the dataset.

    Step 4 - Low-inventory bias adjustment

    • For each product and location, remove all days where opening inventory is below the product-specific threshold obtained in Step 2.
    • This filtering is applied at the daily level — entire days must be excluded regardless of whether sales occurred, or zero sales were recorded.

    Step 5 - Average daily sales

    • Calculate average daily sales per product per location using the filtered dataset.

    Step 6 - Factory warehouse adjustment

    • For the main factory warehouse, compute net demand as the sum of average daily sales across the other three warehouse locations, for each product.

    0.3 Derive Analysis Window¶

    # Today's date
TD = pd.Timestamp.today().normalize()

# The analysis period end date is the most recent Friday:
# If today is Monday to Friday, the end date is last Friday, because this week's business is not yet complete.
# If today is Saturday or Sunday, the end date is this Friday.
if TD.weekday() <= 4: 
    # Monday    is 0, go back 3 days
    # Tuesday   is 1, go back 4 days
    # Wednesday is 2, go back 5 days
    # Thursday  is 3, go back 6 days
    # Friday    is 4, go back 7 days
    ED_ANLY = TD - pd.Timedelta(days=TD.weekday() + 3)
else: 
    # Saturday is 5, go back 1 day
    # Sunday   is 6, go back 2 days
    ED_ANLY = TD - pd.Timedelta(days=TD.weekday() - 4)

# Note: The analysis period is defined as the most recent N complete Monday–Friday weeks.
# So the start date is the Monday of the week that is N weeks before the end date.
SD_ANLY = ED_ANLY - pd.Timedelta(weeks=N_WEEKS) + pd.Timedelta(days=3)

# The data extraction period is defined as the most recent N+1 complete Monday–Friday weeks.
SD_DATA = ED_ANLY - pd.Timedelta(weeks=N_WEEKS + 1) + pd.Timedelta(days=3)
ED_DATA = ED_ANLY

# Summary of the date ranges and number of weeks for the analysis period and data extraction period
print("Analytical period:")
print(f"{SD_ANLY.date()} (Weekday: {SD_ANLY.weekday()}) ~ {ED_ANLY.date()} (Weekday: {ED_ANLY.weekday()}) - {N_WEEKS} weeks")
print("Data extraction period:")
print(f"{SD_DATA.date()} (Weekday: {SD_DATA.weekday()}) ~ {ED_DATA.date()} (Weekday: {ED_DATA.weekday()}) - {N_WEEKS + 1} weeks")
